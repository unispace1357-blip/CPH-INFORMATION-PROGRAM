# STEP 06 로컬 관리자 사용 안내

## 실행과 구조

Node.js 24 LTS를 설치한 담당자 PC에서 프로젝트 폴더를 열고 아래 명령을 실행하세요.

```bash
npm ci
npm run admin:dev
```

관리자는 기본 `127.0.0.1:5190`에만 연결됩니다. Vite는 로컬 개발 화면을 제공하며 관리자 API·DB·외부 로그인은 없습니다. 화면에서도 localhost 접속을 요구합니다. 이 설정은 온라인 관리자 인증 기능이 아니므로 관리자 파일을 외부 사이트에 배포하면 안 됩니다.

`tools/admin/index.html` → `main.tsx` → `AdminApp.tsx`가 독립 진입점입니다. 공개 앱에는 `/admin` 라우트·메뉴·동적 import가 없습니다. 관리자 로컬 빌드는 `npm run admin:build`, 출력은 `dist-admin/`이며 Git에서 제외합니다. 공개 앱과 별도의 Vite 캐시를 사용해 두 개발 서버를 함께 실행할 수 있습니다. 기존 4개 국어 Guest·한국어 Staff와 원본 데이터 구조는 유지합니다.

관리자 메뉴는 **시설 관리 / 호텔 기본 정보 / 데이터 검증 / 가져오기·내보내기**입니다. 1280px 이상의 PC에서 시설 목록과 편집기를 나란히 사용하며 좁은 화면에서는 한 열로 바뀝니다. 공통 색상·시스템 폰트·Button·InformationNotice를 재사용하며 새 라이브러리는 없습니다.

## 작업 데이터와 저장 순서

처음에는 프로젝트의 기존 시설·호텔 JSON을 복사하여 브라우저 메모리에서 작업합니다. 두 파일의 검증 오류는 독립적으로 처리하고 정상 영역은 유지합니다. 관리자에서 저장해도 원본 파일·GitHub·공개 사이트는 바뀌지 않습니다.

1. 시설 또는 호텔 정보를 편집합니다.
2. **편집 내용 저장** 또는 **호텔 편집 저장**을 누릅니다. 검증이 성공하면 현재 브라우저의 작업 데이터에 반영됩니다.
3. **가져오기 / 내보내기**에서 전체 시설·호텔 JSON을 각각 다운로드합니다.
4. PC에 파일이 저장된 것을 직접 확인하고 해당 **파일 저장 확인** 버튼을 누릅니다.
5. 담당자 검수 후 원본 파일에 수동 반영합니다.

화면 상단은 실제 작업 상태에 따라 저장 전 편집, 파일 저장 확인 필요, 검증 오류, DEMO/PRODUCTION, 운영 기술 조건을 표시합니다. 다운로드 요청만으로 변경사항 경고를 해제하지 않습니다. 이후 수정한 내용은 이전 다운로드의 확인으로 지워지지 않습니다. 공개용 시설만 내려받는 것은 전체 원본의 백업이 아닙니다.

## 시설 등록·수정·삭제

시설 목록에는 비공개 시설도 표시합니다. 이름(4개 언어) 검색, 원본 10개 카테고리, 공개/비공개 필터를 AND 조건으로 적용합니다. 목록에서 ID·분류·공개 여부·확인일·개발 검증 상태를 확인하고 **편집**을 누르세요.

새 시설은 **신규 시설 추가**로 시작합니다. ID는 영문 소문자·숫자·하이픈으로 최대 80자이며 중복 ID는 저장할 수 없습니다. 새 시설은 비공개, 확인일 null, 도보시간 null, 언어별 빈 안내·키워드·영어 문구로 시작합니다. 실제 정보를 생성하거나 자동 공개하지 않습니다. 기존 시설 ID는 읽기 전용입니다.

공통 정보에서 카테고리·공개 여부·직접 확인한 날짜·도보시간을 편집합니다. 확인일은 실제 날짜 `YYYY-MM-DD`, 도보시간은 0 이상의 유한한 숫자입니다. 모르면 비워 null로 유지하세요. 숫자를 추정하거나 현재 영업 여부를 계산하지 않습니다.

**삭제**는 대상 이름과 ID를 보여주고 확인을 받습니다. 취소하면 목록·편집 내용이 유지됩니다. 확인하면 현재 작업 데이터에서 해당 시설만 삭제하며 원본 파일은 그대로입니다.

## 4개 국어·키워드·영어 문구

한국어·English·简体中文·日本語 버튼으로 편집 언어를 선택하세요. 각 언어의 시설명·설명·주소·영업시간·이동 안내·참고 사항·휴무일·검색 키워드를 개별 편집합니다. 다른 언어는 변경하지 않으며 자동 번역하지 않습니다. 여러 줄 안내는 그대로 보존합니다.

기존 스키마는 **시설명 4개 언어 모두 입력**을 요구합니다. 입력 중 빈 이름을 유지할 수 있지만 빈 이름으로 편집 저장·정상 JSON 내보내기는 차단됩니다. 설명·주소·영업시간·이동 안내·참고 사항·휴무일은 개발 데이터에서 빈 문자열을 허용합니다. 운영용 공개 시설은 기존 운영 검증의 필수 항목을 모두 채워야 합니다. 스키마를 완화하거나 가짜 이름을 자동으로 넣지 않았습니다.

키워드는 **검색 키워드 추가** 후 각 항목을 입력하고 필요하면 수정·삭제합니다. 공백 및 NFC·대소문자·앞뒤 공백 정규화 후 같은 키워드는 거부합니다. 항목을 조용히 삭제하거나 중복 제거하지 않으므로 오류가 표시되면 직접 고치세요.

영어 응대 문구는 독립 항목으로 추가·수정·삭제하며 위로/아래로 순서를 바꿀 수 있습니다. 저장·내보내기는 기존 `englishPhrases: string[]`를 유지해 Staff의 개별/전체 복사와 호환됩니다. 영어 문장 생성 기능은 없습니다.

## 호텔 정보

호텔 메뉴는 시설과 별개로 관리합니다. 데이터 상태·확인일·공통 체크인/체크아웃 시간, 언어별 호텔명·설명·주소·체크인·체크아웃·조식·주차·객실 이용·참고 사항을 편집합니다.

시간은 `00:00`~`23:59`의 `HH:mm`입니다. 미확인이면 비워 null로 유지하며 기본 체크인/체크아웃 시간은 제공하지 않습니다. 빈 호텔 데이터는 개발 검증에 유효합니다. 실제 운영 정책·번역은 담당자가 직접 확인해야 합니다.

## JSON 가져오기

시설 JSON과 호텔 JSON을 각각 선택합니다. 파일 이름은 자유롭지만 내용은 해당 스키마여야 하며 최대 **2MB(UTF-8 바이트 기준)**입니다. JSON 문법·schemaVersion 1·언어 구조·타입·카테고리·ID 중복·날짜/시간·키워드 등을 기존 검증기로 확인합니다.

검증 성공 후 교체 확인을 받습니다. 취소하거나 파일이 잘못되면 현재 데이터는 유지됩니다. 한 파일을 가져와도 다른 파일은 변경하지 않습니다. 오류가 나도 앱 전체를 종료하거나 대체 데이터를 만들지 않습니다. 구버전 호환 기본값은 기존 파서의 규칙에 따라 보완하되 입력 파일 자체를 수정하지 않습니다. 외부 문자열은 React 일반 텍스트로 표시합니다.

## JSON 내보내기

**전체 시설 JSON 다운로드**는 비공개까지 포함하는 `facilities.json`, **호텔 JSON 다운로드**는 `hotel.json`입니다. UTF-8 JSON으로 언어 문자열·모든 데이터 필드·schemaVersion을 보존하며 편집기 ID·탭·필터 등 임시 상태는 넣지 않습니다. 내보내기 후 재불러오기 결과가 같습니다.

저장 전 편집은 먼저 저장하거나 취소해야 합니다. 스키마/키워드 검증에 실패한 정상 JSON은 내보내지 않습니다. 전체 파일은 관리자 편집용이며 기술적으로 운영 준비가 되지 않았으면 배포하지 마세요. 파일 다운로드와 디스크 저장은 브라우저/사용자 동작에 따르므로 내려받은 파일을 직접 확인한 뒤 확인 버튼을 누르세요.

## 검증 오류와 운영 상태

시설·호텔 개발 검증과 현재 운영 배포 검증을 따로 표시합니다. **운영 전환 전 필수 정보 검사**는 두 상태를 production이라고 가정한 복사본으로 기존 `validateProductionData`를 실행하며 실제 상태를 바꾸지 않습니다. 따라서 DEMO의 상태 오류와 누락된 정보·확인일을 별도로 확인할 수 있습니다.

오류는 시설 ID/목록 번호·언어·필드와 수정 안내를 가능한 범위에서 표시합니다. 상세 기술 오류도 펼쳐 볼 수 있습니다. 저장 실패 시 입력·작업 데이터를 유지하므로 오류를 직접 수정하고 다시 저장하세요.

DEMO에서 PRODUCTION으로 전환하려면 필수 정보 검사를 통과하고 별도 확인을 받아야 합니다. 한 데이터의 상태 변경으로 다른 데이터 상태를 자동 전환하지 않습니다. 운영 준비가 부족하거나 미래 확인일이 있으면 전환을 차단합니다. 가져온 파일의 상태는 유지하되 운영 검사 FAIL이면 준비 완료로 표시하지 않습니다.

검증 PASS는 형식·필수 값·날짜 조건을 만족한다는 뜻이며 실제 시설 존재·주소·영업시간·휴무일·정책·번역의 정확성을 보증하지 않습니다. 현재 원본은 계속 demo이며 실제 호텔 정책을 입력하지 않았습니다.

## 미저장 내용 보호

저장 전 편집이 있을 때 다른 시설 선택, 메뉴 이동, 편집 취소는 버릴지 확인합니다. 취소하면 현재 입력을 유지합니다. JSON 교체도 검증 후 별도 확인을 받습니다. 저장한 작업 데이터는 메뉴 이동으로 사라지지 않습니다.

저장 전 편집 또는 아직 파일 저장을 확인하지 않은 변경이 있으면 `beforeunload` 경고를 등록합니다. Chromium에서 새로고침 취소 시 입력 유지, 승인 시 원본 demo로 재시작을 확인했습니다. 브라우저 강제 종료·기기 오류·브라우저 정책 때문에 경고가 생략될 수 있으므로 완전한 복구/저장을 보장하지 않습니다. 자동 파일 쓰기·클라우드 저장·브라우저 영구 저장은 구현하지 않았습니다.

## 공개용 데이터와 빌드 안전성

**공개 시설 선별 미리보기 다운로드**는 같은 스키마의 `facilities.public.json`에서 `isPublished: false` 시설을 완전히 제거합니다. DEMO 상태는 그대로이며 운영 배포할 수 없습니다. **운영 검증 후 공개 시설 다운로드**는 현재 두 데이터의 운영 검증이 성공해야 사용할 수 있습니다. 전체 원본 백업과 구분하세요.

고객 배포용 명령:

```bash
npm run validate:production
npm run build:production
```

운영 빌드 순서:

1. 기존 원본 시설·호텔 스키마 검증(비공개 시설도 구조 검사).
2. 공개 시설만 같은 스키마로 선별.
3. 기존 운영 필수 안내·확인일·production 조건 검사.
4. OS 임시 폴더에 검증 스냅샷 생성.
5. `customer-production` 모드의 Vite가 원본 JSON 대신 검증 스냅샷만 사용.
6. 관리자 모듈 의존성·관리자 HTML/코드/스타일 검사 후 `dist-production/` 출력. 오류 시 빌드 실패.

Node 파일·경로 API를 사용하며 `cp`, `rm` 등 OS 전용 셸 명령에 의존하지 않습니다. 원본 JSON을 덮어쓰지 않고 임시 스냅샷은 정리합니다. 이 모드를 스냅샷 없이 직접 실행하면 차단됩니다. 개발 `npm run build`는 기존 demo/전체 데이터 방식을 유지하며 공개 앱에 관리자 코드는 포함하지 않습니다. `dist/`에는 비공개 원본이 포함될 수 있으므로 고객 배포에 사용하면 안 됩니다. `dist-admin/`은 관리자 로컬 검사 결과로 공개 배포하지 않습니다.

공개 저장소의 전체 원본 JSON은 GitHub에서도 읽을 수 있습니다. 비공개 시설이라도 비밀번호·토큰·고객 개인정보·내부 계약 조건은 넣지 마세요. 번들 제외는 게시 데이터 선별이며 인증/비밀 저장 기능이 아닙니다.

## GitHub 수동 반영

1. 내려받은 전체 `facilities.json`과 `hotel.json`을 별도 백업합니다.
2. 담당자가 실제 정보·4개 언어 번역·확인일·공개 여부를 검수합니다.
3. 검수된 전체 파일을 `src/data/facilities.json`, `src/data/hotel.json`에 수동 반영합니다. 공개 미리보기 파일로 전체 원본을 덮어쓰지 마세요.
4. 개발 검증·테스트·lint·build를 실행하고 운영을 준비할 때 production 검증도 실행합니다.
5. 변경 내용을 검토하여 GitHub에 수동 커밋·푸시합니다. 도구에 계정 인증·자동 업로드 기능은 없습니다.
6. 실제 배포는 별도 승인된 단계에서 `dist-production/`만 사용합니다. 이번 단계에서는 배포하지 않습니다.

신규 자동 테스트는 관리자 작업 29개, 공개 스냅샷·실제 Vite 빌드·개발 캐시/로컬 설정 6개입니다. 기존 131개 테스트 파일과 원본 JSON·스키마·타입·검증기는 변경하지 않았습니다. production 형태의 Fixture는 가상의 독립 검증 자료이며 원본에 저장하지 않습니다.

실제 생성된 JavaScript·JSON·HTML·CSS·map 텍스트에서 비공개 ID·언어별 이름/설명/주소/안내/참고/휴무/키워드·영어 문구의 고유 문자열 **34개가 모두 없는지** 검사했습니다. 공개 시설/호텔 검증 문자열은 포함됨을 확인했습니다. 관리자 코드·HTML·스타일도 없고 원본 파일 바이트는 동일했습니다. 개발 공개 `dist/`에도 관리자 코드는 없습니다.

### 브라우저 QA 재실행

Playwright는 앱 의존성에 추가하지 않았으며 별도 QA 환경의 기존 도구와 Chromium을 사용합니다.

```bash
# 터미널 1: 공개 개발 화면
npm run dev -- --host 0.0.0.0 --port 5175 --strictPort
# 터미널 2: 로컬 관리자
npm run admin:dev

# 터미널 3: 이 클라우드 QA 환경
NODE_PATH=/tmp/cph-browser-check/node_modules \
CPH_UI_ARTIFACT_DIR=/workspace/exports/step06-admin \
npm run test:admin-ui

NODE_PATH=/tmp/cph-browser-check/node_modules \
CPH_UI_BASE_URL=http://127.0.0.1:5175 \
CPH_UI_ARTIFACT_DIR=/workspace/exports/step06-staff \
npm run test:staff-ui

NODE_PATH=/tmp/cph-browser-check/node_modules \
CPH_UI_BASE_URL=http://127.0.0.1:5175 \
CPH_UI_ARTIFACT_DIR=/workspace/exports/step06-guest \
npm run test:guest-ui

NODE_PATH=/tmp/cph-browser-check/node_modules \
CPH_UI_BASE_URL=http://127.0.0.1:5175 \
CPH_UI_ARTIFACT_DIR=/workspace/exports/step06-regression \
npm run test:ui
```

`CPH_ADMIN_BASE_URL`은 관리자 QA 주소, `CPH_CHROMIUM_PATH`는 Chromium 경로입니다. 위 환경변수 지정 문법은 이 Linux QA 환경의 예시이며 일반 담당자는 `npm run admin:dev`만 사용하면 됩니다. 다른 환경에 QA 도구가 없거나 검사를 실행하지 못하면 미검증으로 보고합니다.
