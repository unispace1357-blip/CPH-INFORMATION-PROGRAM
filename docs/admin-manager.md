# 로컬 관리자

Node.js 24 LTS에서 `npm ci`, `npm run admin:dev`로 실행합니다. localhost 전용이며 서버 API·DB·로그인·자동 GitHub 업로드는 없습니다. 독립 진입점은 `tools/admin/`, 로컬 빌드는 `npm run admin:build` → `dist-admin/`입니다. 공개 앱에는 관리자 경로·코드가 없습니다.

## 편집과 저장

1. 시설 관리에서 이름 검색·카테고리·공개 여부로 찾고 **편집**을 선택합니다. 현재 실제 시설 23개는 개발 미리보기에서 공개 상태이며 DEMO입니다.
2. 언어를 선택해 시설명·주소·영업시간·휴무일·안내·키워드를 편집합니다. 영어 응대 문구는 별도 목록입니다. 다른 언어는 자동 변경하지 않습니다.
3. **편집 내용 저장**은 브라우저 작업 메모리에만 반영됩니다. 원본 JSON이나 GitHub를 자동 수정하지 않습니다.
4. **가져오기 / 내보내기 → 전체 시설 JSON 다운로드**로 파일을 받고 실제 저장을 확인한 뒤 파일 저장 확인 버튼을 누릅니다. 호텔은 별도 파일입니다.
5. 내려받은 파일을 백업하고 검수한 내용을 `src/data/facilities.json`에 수동 반영합니다. 승인 호텔 원고는 임의 수정하지 않습니다. 검증 후 변경 파일을 Git에 커밋합니다.

새 시설은 비공개·미확인 값으로 시작하고 ID는 중복 불가, 기존 ID는 변경할 수 없습니다. 삭제·미저장 내용 이탈·파일 교체에는 확인이 있습니다. 자동 영구 저장/복구는 없으므로 브라우저 종료 전에 전체 JSON을 저장하세요. 공개 선별 파일은 전체 원본의 백업이 아닙니다.

확인일·도보시간·지도 URL은 실제 근거가 있을 때만 입력합니다. 지도 입력란을 비우고 저장하면 null이 됩니다. 등록 링크 확인 전에 호텔 출발·정확한 지점·이동수단·실제 연결을 직접 확인하세요. 검증기는 장소의 정체성을 자동 확인하지 않습니다.

## JSON 왕복·검증

시설/호텔 파일은 각각 최대 2MB UTF-8 JSON이며 기존 타입·스키마·버전·4개 언어·중복 ID·날짜·URL을 검증합니다. 잘못된 파일은 현재 작업 데이터를 교체하지 않습니다. 전체 내보내기→재불러오기는 모든 필드·원본 URL·언어 문자열을 보존합니다. 저장 전 편집이나 무효 데이터가 있으면 정상 내보내기를 차단합니다.

**데이터 검증**은 개발 검증과 운영 배포 검증을 구분합니다. 현재 개발 검증은 PASS, 운영 검증은 DEMO와 미확인 정보 때문에 FAIL이어야 정상입니다. `isPublished: true`는 미리보기 표시 제어이며 production 전환이나 배포 승인이 아닙니다. 공개 원본에 개인정보·비밀 정보를 넣지 않습니다.

배포 보호는 [데이터 계약](data-model.md), 승인 호텔 원고/H33은 [원고 기준](step07a-hotel-data.md)을 따릅니다. 실제 운영 배포·QR 배포는 별도 승인 전 진행하지 않습니다.
