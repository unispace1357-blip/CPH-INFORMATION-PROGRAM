## hotel.json 결과

```text
schemaVersion: 1
dataStatus: demo
lastVerifiedAt: 2026-10-15
checkInTime: 15:00
checkOutTime: 12:00
translations: ko / en / zh-CN / ja
  name, description, address, checkIn, checkOut,
  breakfast, parking, roomUsage, notes
```

기존 타입·JSON Schema를 유지하며 새 카테고리·데이터 필드·정책을 만들지 않았습니다. 공통 시간과 문장 속 시간 표기는 승인 원문 형태를 각각 유지합니다. 영어 3:00 PM, 한국어 오후 3시 등을 임의로 바꾸지 않았습니다.

## 주요 규정 대조

- 체크인 15:00 / 체크아웃 12:00, 별도 신분증 제출·보증금 요구 없음: H04~H06 및 공통 값과 일치.
- 조식 1층 High Wave/하이웨이브, 06:30~10:00·마지막 입장 09:30: H07~H09의 각 언어 표현 유지.
- **성인 조식 32,000원**, 5~8세 어린이 19,000원, 현장 객실 번호 확인: H10~H12 모든 언어 일치. 원화는 KRW/韩元/ウォン으로 원문대로 유지하며 환산하지 않았습니다.
- 키 1개당 11,000원, 체크아웃 초과 시간당 11,000원·17:00 이후 1박 요금: H31~H32 문장 그대로.
- 흡연 청소비 200,000원: H23의 조건 및 '청구될 수 있음' 표현 그대로.
- **반려동물은 지정 전용 객실에서만 가능, 일반 객실 불가**: H34를 4개 언어 notes에 반영하고 프론트 신고 H35도 유지.
- 반려동물 침구 오염 50,000원, 가구 품목별 손상 비용, 미신고 시 기존 추가 비용 외 22,000원: H27~H29 조건/가능 표현 그대로.
- 무료 주차·차량 등록 불필요, Wi-Fi CPH_층수·비밀번호 없음, 전자레인지 6/10/16층, 인근 CU, 냉방·일회용품·배달·소방점검·금연·소란·비품 규정: H13~H26 지정 필드에 모두 반영.
- 대표전화: 한국어 `032-310-5000`, 다른 3개 언어는 승인 원문 `+82-32-310-5000` 그대로. H33 문자 번호로 대체하지 않았습니다.

표현 확인 참고: H32의 한국어 '오후 5시 이후'·일본어 '午後5時以降'·영어 'after 5:00 PM'은 정각 포함 여부의 해석 여지가 있습니다. 원문을 임의 수정하거나 정각/요금 중복 정산 조건을 새로 만들지 않았습니다. 추가 명확화가 필요하면 담당자가 새 원고로 승인해야 합니다.

## H33 공개 보류 기록

비대면 체크아웃 절차 자체는 현행이지만 문자 수신번호의 고객 공개 승인이 확인되지 않았습니다. 원본에도 실제 번호가 없고 '지정된 연락처'로만 적혀 있습니다. 따라서 고객 JSON·실행 화면에 H33을 넣지 않았습니다.

**한국어 원문**

프론트를 거치지 않는 퇴실은 객실 키 2개를 테이블에 놓고 객실 번호와 퇴실 사실을 지정된 연락처로 문자 발송해야 합니다.

**English 원고**

For check-out without visiting the front desk, leave both room key cards on the table and text your room number and check-out notice to the designated hotel contact.

**简体中文 원고**

无需前往前台办理退房时，请将两张房卡放在桌上，并向酒店指定号码发送房号及退房短信。

**日本語 원고**

フロントに立ち寄らずチェックアウトする場合は、カードキー2枚をテーブルに置き、客室番号と退室の旨をホテル指定の連絡先へSMSでお送りください。

문자 수신번호와 공개 승인을 별도로 확인해야 합니다. 대표전화 032-310-5000으로 임의 대체하지 않습니다. 공개 승인 이후 담당자가 번호를 포함한 4개 언어 최종 문구와 checkOut 배치를 승인하고, 검증 기준·H33 제외 조건·관련 테스트를 함께 업데이트한 뒤 반영하세요. 이번 단계에서는 공개하지 않습니다.

## 고객 UI와 관리자 호환

기존 호텔 5개 카테고리를 유지합니다. topic/notes의 빈 줄을 안전한 React `<p>`로 나누고 문단 사이에 여백을 두며 단일 문단 내부 줄바꿈도 유지합니다. HTML 주입·번역·금액 계산은 없습니다. 체크인/체크아웃 공통 시간은 별도 항목으로 표시합니다. 조식 시간·입장·요금은 각각 독립 문단으로 읽을 수 있습니다.

주변 시설은 **기존 가상 6개 그대로**, 공개 시설 5개만 UI에 표시됩니다. 개발 경고는 유지하되 '주변 시설 가상·고객 공개/실제 안내 금지'를 4개 언어로 명확히 안내합니다. 승인 호텔을 가상 호텔이라고 표시하지 않습니다. 두 dataStatus는 demo, 실제 배포 미실시, 실제 고객 공개 금지입니다.

실제 승인 hotel.json을 관리자에서 열고 4개 언어·공통 값, 파일 가져오기·같은 JSON 내보내기·브라우저 임시 편집·재불러오기·개발 검증을 확인했습니다. QA 편집은 메모리에서만 수행했으며 실제 파일을 바꾸거나 승인 문구를 가상 값으로 되돌리지 않았습니다.

`validate:hotel-copy`는 35개 ID·셀 해시·최종 매핑·순서/문단 수·각 셀 원문·H33 제외·description 미완성·확정 공통 값·demo를 비교합니다. 불일치 시 ID/언어/필드/승인 값/실제 값을 출력하고 종료 코드 1이며 자동으로 고치지 않습니다. 원본 XLSX를 독립적으로 다시 읽어 추출 기준의 140개 셀과 실제 반영 136개 셀·행 위치도 모두 직접 대조했습니다.

## STEP 06 잔여 빌드 안전성 보완

`build:production`의 첫 단계가 고정 `dist-production/`을 정리하도록 변경했습니다. 이후 사전 운영 검증·타입 검사·빌드가 실행되므로 검증 실패 전에 오래된 산출물이 제거됩니다. 직접 buildProduction 함수를 실행해도 정리 후 입력 JSON을 읽습니다. 체크아웃·src/data·시스템 임시 루트 등 위험한 정리 경로는 거부하며 테스트 전용 임시 하위 폴더만 별도로 허용합니다.

오래된 기본 출력에 가짜 marker를 넣고 실제 npm build:production을 실행해 예상 종료 코드 1과 출력 폴더 부재를 확인했습니다. 누락/잘못된 JSON·demo 실패 후에도 이전 파일이 남지 않았고 새 빌드는 생성되지 않았습니다. 기존 실제 Vite Fixture 테스트에서 비공개 고유 문자열 34개 및 관리자 코드/HTML/스타일이 제외되는 정책도 계속 통과합니다.

## 남은 항목과 STEP 07-B

description 4개 언어는 미승인/미완성으로 빈 문자열입니다. 시설을 production으로 가정해도 기존 운영 검증이 호텔 description 누락을 차단합니다. H33 문자 번호·공개 승인도 별도 확인 사항입니다. source 문구는 사용자 승인이며 별도 번역기/원어민 감수 완료로 표시하지 않습니다.
